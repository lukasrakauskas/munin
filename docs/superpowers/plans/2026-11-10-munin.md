# Munin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Build a minimal, local-first Markdown editor with Rune and RuneKit.

**Architecture:** Rune `AppSpec` owns a small state and view. RuneKit supplies the text area, tree, menus, dialogs, and shell components where they fit. Rust filesystem code owns disk operations and safe saving; a small local preferences file stores restoration data.

**Tech Stack:** Rust, Rune and RuneKit pinned to one Git revision, a cross-platform native folder picker if needed.

**Spec:** `docs/superpowers/specs/2026-11-10-munin-design.md`

## Global Constraints

- Linux is the first tested platform; retain Windows and macOS portability.
- Markdown files are the source of truth; no backend, database, cloud, preview, tabs, or custom text engine.
- Follow Rune examples and use RuneKit components. Default to system theme, with light and dark overrides.
- Do not discard unsaved changes on a save failure or external modification.
- Keep the app runnable after each task. Do not commit the user's pre-existing untracked files without permission.

## Review Focus

- Failed save while switching files: keep the old editor and buffer; test in Task 3.
- File modified externally: never silently overwrite it; test in Task 3.
- Missing restored workspace or file: start normally; test in Task 2.
- Unicode paths and text: preserve bytes and names; test in Tasks 2 and 3.
- Unsafe or conflicting names, symlink recursion, and deletion confirmation: reject or avoid them; test in Task 4.

## Files

- `Cargo.toml`: pinned Rune dependencies and minimal cross-platform dependencies.
- `src/main.rs`: app initialization, Rune view, and event routing.
- `src/fs.rs`: workspace tree and safe filesystem operations.
- `src/state.rs`: workspace, editor, saves, dialogs, and preferences.
- `src/ui.rs`: RuneKit sidebar and writing surface, if separation helps.
- Tests live alongside the code they exercise.

### Task 1: Runnable Rune shell

**Files:** Modify `Cargo.toml`, `src/main.rs`.

**Interfaces:** `main()` starts a Rune `AppSpec`; the application state and `view` follow `examples/hello`.

- [ ] Inspect Rune's current `dev` revision, `examples/hello`, and RuneKit `shell`, `tree`, and `rich_editor` examples. Pin `rune` and `rune-kit` to the same revision.
- [ ] Add a headless runtime test that constructs the empty app and asserts a writing surface and sidebar are present.
- [ ] Run the test and confirm it fails before implementing the shell.
- [ ] Implement the minimal two-pane RuneKit window with empty-state text and system theme.
- [ ] Run `cargo test` and `cargo run`; confirm the test passes and the window opens, or report an environment blocker.

### Task 2: Workspaces and tree

**Files:** Create `src/fs.rs`, `src/state.rs`; modify `src/main.rs` and optionally create `src/ui.rs`.

**Interfaces:** `fs::scan_workspace(root: &Path) -> io::Result<Vec<PathBuf>>` returns workspace-relative Markdown files; state owns the selected workspace and RuneKit tree model.

- [ ] Write tests for nested Markdown paths, Unicode names, omission of non-Markdown files and directory symlinks, and a missing restored workspace/file that does not prevent startup.
- [ ] Run the new tests and confirm they fail.
- [ ] Implement folder selection using a Rune primitive or a small cross-platform picker, filesystem scan, expandable RuneKit tree, and local preference restoration. Preserve folders even when empty so users can create notes inside them.
- [ ] Run `cargo test`; manually open a directory and verify folder expansion and Markdown-only file entries.

### Task 3: Editing and reliable saving

**Files:** Modify `src/fs.rs`, `src/state.rs`, `src/main.rs`, `src/ui.rs` if present.

**Interfaces:** state opens files into Rune `TextEdit`, tracks dirty state and disk identity, and exposes save and file-switch operations returning errors without losing the buffer.

- [ ] Write tests that open and save Unicode text, save before switching, retain the original dirty buffer after a write failure, and detect an externally modified file without overwriting it.
- [ ] Run the tests and confirm they fail.
- [ ] Implement file loading and RuneKit `TextArea`, debounced autosave, explicit immediate save, safe writes, external-change detection, and visible error reporting. Retain the buffer and block destructive transitions when save fails. Use RuneKit syntax decorations if available.
- [ ] Run `cargo test`; exercise typing, selection, undo, clipboard, IME, autosave, and scrolling in the Linux window.

### Task 4: File operations and navigation

**Interfaces:** filesystem operations return `io::Result`; state validates names and refreshes the tree after successful changes.
